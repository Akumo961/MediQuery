# MediQuery — Commercial Sale Package

## Positioning

MediQuery is offered as a **health-tech software asset**: a secure, owner-isolated medical-report organization platform with deterministic PDF extraction, page-level evidence, account controls, testing, and deployment documentation.

It is **not** offered as a certified medical device, diagnostic product, or autonomous clinical AI system.

## Buyer value proposition

A buyer receives:

- FastAPI backend and authenticated report lifecycle.
- Streamlit reference client.
- Deterministic PDF extraction and evidence preservation.
- Owner/tenant isolation and account deletion controls.
- Security, safety, deployment, architecture, and buyer-diligence documentation.
- Automated tests, including the primary E2E journey.
- Docker production-shaped API deployment configuration.
- A clean separation between implemented functionality and future AI capabilities.

## Demonstrable workflow

`Signup → Login → Upload PDF → Processing → Extracted Values → Evidence → Report History/Detail → Account Deletion`

Use synthetic laboratory PDFs only during demonstrations.

## What the buyer is not being promised

Do not promise:

- Clinical diagnosis or treatment recommendations.
- Regulatory approval or medical-device clearance.
- HIPAA/PIPEDA/PHIPA/GDPR/SOC 2 certification.
- Clinical validation.
- Production authorization for real patient data.
- An implemented LLM/RAG diagnostic workflow.
- Customer revenue or traction unless independently documented.

## Pricing strategy

Use a **negotiation anchor**, not a claim that the software has a guaranteed market value.

Suggested opening acquisition ask: **CAD $100,000+**, subject to buyer diligence, IP ownership, technical review, and transaction scope.

Possible structures:

1. Full IP/software acquisition.
2. Asset acquisition with source-code transfer and documentation.
3. Exclusive commercial licence plus support transition.
4. Acquisition with a short technical handover period.

Any final price should be based on buyer value, strategic fit, replacement cost, speed-to-market, IP cleanliness, and demonstrated technical quality — not on the number of source-code files.

## Required transaction package

- Exact release commit SHA.
- Source repository transfer/licence terms.
- Dependency and licence inventory.
- Contributor/IP ownership declarations.
- Security and threat-model documents.
- Test and CI evidence.
- Deployment requirements.
- Medical safety boundary.
- Known limitations and unresolved operational items.
- Demonstration script and synthetic demo data.
- Buyer handover checklist.

## Buyer objection handling

**“Is this really AI?”**

Answer: The protected report workflow is intentionally deterministic and evidence-first. No LLM is claimed or required. Future grounded AI can be added behind replaceable service boundaries.

**“Is it clinically validated?”**

Answer: No. It is an engineering/software asset, not a clinically validated medical device.

**“Can we use real patient data immediately?”**

Answer: Not from the repository alone. A production deployment requires managed infrastructure, privacy/security review, operational controls, and the buyer's applicable legal/regulatory approvals.

**“What makes it valuable?”**

Answer: The buyer receives a working end-to-end secure document workflow, evidence-preserving extraction, authorization/isolation controls, deletion behavior, tests, CI, Docker deployment shape, and due-diligence documentation rather than a prototype screen or isolated code sample.
