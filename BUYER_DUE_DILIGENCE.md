# Buyer due diligence

## Why pay $150k instead of building it?

Today, a rational buyer would not pay $150k solely for the code. Commodity frameworks and models can reproduce the original prototype quickly. The value proposition is a head start toward a disciplined, safety-conscious report workflow: structured evidence, a secure product boundary, documentation, and a deployable architecture direction. A $150k valuation becomes more credible only with validated differentiated workflow/IP, operational maturity, defensible customer traction, and clean rights.

## Reasons to say no

| Area | Current risk | Technical response |
| --- | --- | --- |
| Product | No verified market demand, revenue, or retention | Cannot be fixed by code; obtain honest customer evidence. |
| Clinical/AI | No validation; legacy vision model was placeholder | Disabled unsafe route; fund evaluation and clinical review. |
| Security/privacy | Local foundation only; no production controls | Implement managed deployment, review, and evidence. |
| IP | No `LICENSE`; bundled virtual environment and model/data rights unclear | Add licence after counsel review; rewrite history and inventory licences. |
| Infrastructure | No live managed environment or reliability record | Build, monitor, and document a production deployment. |
| Competition | Low technical barrier | Build proprietary workflow/data partnerships only with valid rights. |

## Acquisition blockers

No clean licence/rights package, deployment evidence, clinical validation, privacy/compliance review, customer traction, or clean Git history exists yet. These are material blockers, not issues a README can solve.
